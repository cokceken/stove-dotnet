## StoveDotnet 0.2.0

This release freezes the API ahead of 1.0. It breaks 0.1.x in the places listed under **Upgrading**; nothing further
is planned to change before 1.0 unless use of 0.2 turns something up. It contains the same code as
`0.2.0-preview.2`.

### Highlights

- **Failures explain themselves without setup.** A failed test reports the HTTP requests it sent with their response
  bodies, and the application's logs with exception stack traces, whichever assertion library failed.
- **Traces without a collector.** `WithTelemetry()` captures the application's activities in-process. No exporter or
  OpenTelemetry setup is required, and spans are available as soon as they finish.
- **Startup failures name what failed.** `StoveStartupException` names the system or application, repeats the cause
  and lists every system that failed in a parallel start.
- **One name per concept.** `Migrations` and `Peek` in every module; every `Should*` method waits by default and
  returns as soon as its condition holds.
- **Documented API.** Every public member has XML documentation in the package.
- **Fewer packages.** Test time lives in `StoveDotnet.Hosting`; `StoveDotnet.Time` is gone.

### Upgrading from 0.1.x

**Packages**

- Use the same version of every StoveDotnet package. They now depend on each other with exact versions, so a mixed
  set fails at restore.
- Remove `StoveDotnet.Time`. `UseStoveTime(clock)` and `t.Clock(name)` are in `StoveDotnet.Hosting` (referenced by
  `StoveDotnet.AspNetCore`), namespace `StoveDotnet.Hosting`.
- `t.Using<T>()` and `t.Services()` moved to the `StoveDotnet.Hosting` namespace.

**Renamed**

| 0.1.x | 0.2 |
| --- | --- |
| `o.Setup` (MongoDB, RabbitMQ, Azure Service Bus) | `o.Migrations` |
| `MongoDbSetupContext`, `RabbitMqSetupContext`, `AzureServiceBusSetupContext` | `…MigrationContext` |
| `UseExisting(..., runSetup:)`, `runTopologySetup:` | `runMigrations:` |
| `t.Kafka().PeekAsync<T>()` | `await t.Kafka().Peek<T>()` |
| `t.RabbitMq().Peek<T>()` | `await t.RabbitMq().Peek<T>()` |
| `SpanRecord.ServiceName` | `SpanRecord.Source` (the activity source name) |

**Removed**

- `ShouldQuery` on PostgreSQL, SQL Server, MySQL and MongoDB. Use `Query` and assert on the rows; wrap both in
  `Eventually.AssertAsync` when the application writes asynchronously.
- `WireMockSystem.CallsFor` (use `Requests`), `IAfterApplicationStarted` (use `IAfterApplicationsStarted`).
- `t.Telemetry().Logs()`, `LogRecord` and the OTLP options of `TelemetryOptions`. `WithTelemetry()` no longer exposes
  `OTEL_*` configuration. Application logs in failure output are unaffected.
- KafkaSystem's Schema Registry plumbing (`NeedsRegistryNetwork`, `RegistryNetwork`, `RegistryBootstrapServers`).

**Changed behaviour**

- `Eventually.AssertAsync` retries every exception in both overloads. `Eventually.UntilAsync` polls a value and lets
  an exception from its probe propagate. `EventuallyOptions.RetryOn` overrides either. Zero and infinite timeouts are
  no longer accepted.
- A startup failure is thrown as `StoveStartupException`; the original exception is its `InnerException`.
  Cancellation is not wrapped.
- WireMock `ShouldHaveBeenCalled` waits up to `WireMockOptions.DefaultTimeout` (5 seconds) for the requests, so a
  failing assertion takes that long. Pass `within:` to shorten it.
- Failure output no longer includes framework logs below Warning (`Microsoft.*`, `System.*`), which drops EF Core SQL
  command logs.
- Without ASP.NET Core instrumentation, request spans are named `Microsoft.AspNetCore.Hosting.HttpRequestIn` and carry
  no route or status. Register the application's usual OpenTelemetry instrumentation for detail; no exporter is needed.

### Not changed

Kafka keeps both `IStoveKafkaSerde` and `IStoveKafkaAsyncSerde`.
